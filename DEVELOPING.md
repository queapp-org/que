# Developing que

Running que from source, and how the pieces fit. Setting up a checkout (`npm ci`, `npm run dev`)
and the checks to run before a pull request (`npm run verify`) are in
[CONTRIBUTING.md](CONTRIBUTING.md).

## Building the app

```sh
npm run package   # an unsigned que.app in release/mac-arm64
npm run dist      # the DMG and zip
```

## Running from source

```sh
npm run install:local
```

Builds que.app from your checkout, replaces `/Applications/que.app` with it, links the `que`
command (`/usr/local/bin/que` when that is writable, else `~/.local/bin/que`), and reopens the
app. It never touches the background service, so every terminal keeps running. To upgrade, pull
`main` and run it again. `--no-build` installs the app `npm run package` already made, `--dest`
installs somewhere else, `--no-link` and `--no-launch` skip those steps. The app it builds
never checks for newer releases, and neither does one run from source; you follow `main`.

The terminals live in the background service (the daemon), which keeps running the build it
started with. A change to the service itself reaches the running one only through an update in
place: when a rebuild or an update changes it, Restart appears at the right end of the sidebar's
Quiet row; it hands every terminal to the new build without ending any, and `que daemon upgrade`
does the same from the CLI. If the handoff is refused, the running service keeps serving as it was
and the error line says why. The app never ends a terminal to do this; `que daemon restart` does,
stopping the service and starting the new build, when you want it regardless. When a newer que
release is published, the same place reads Update in a release build: it downloads the release,
and a click on Restart installs it, relaunches, and hands the terminals over at launch. Only a
release build (`npm run dist`) does this, and only it has the `app-update.yml` the updater reads,
because electron-builder writes that file for the dmg and zip targets and not for
`npm run package`'s app directory. The updater library sits in `devDependencies` so that
electron-vite bundles it: `electron-builder.yml` leaves `node_modules` out of the app, and
`npm run smoke:packaged` fails if it stops loading from `app.asar`.

## How the pieces fit

| Path                                         | What lives there                                                      |
| -------------------------------------------- | --------------------------------------------------------------------- |
| `src/daemon/`                                | the daemon: terminals, workspaces, status engine, quiet hours, SQLite |
| `src/shared/`                                | the socket protocol, the client, paths, config                        |
| `src/cli/`                                   | the `que` CLI                                                         |
| `src/main/`, `src/preload/`, `src/renderer/` | the Electron app                                                      |
| `tests/`                                     | daemon integration tests, Playwright specs, subprocess fakes          |
| `scripts/`                                   | build, smoke, packaged smoke, flake hunt, docs                        |

The architecture in depth: [docs/architecture.md](docs/architecture.md). How it looks and why:
[docs/design.md](docs/design.md). Tests follow the three guides in `.claude/skills/`
(`test-planning`, `vitest-testing`, `e2e-testing`); see [CONTRIBUTING.md](CONTRIBUTING.md).

`docs/cli.md` and `docs/configuration.md` are generated by `npm run docs`; queapp.org builds its
CLI and configuration references from them at each release.

What is next: the [open issues](https://github.com/queapp-org/que/issues). Vulnerabilities:
[SECURITY.md](SECURITY.md).
